## 第 1 步：跑通模型调用 + 记忆聊天机器人

### 1.1 最小调用：理解 messages 体系

LLM API 的全部世界观在一个数组里——`messages`。它没有"会话"概念，**所谓多轮对话，就是把完整历史每次都重新发一遍**：

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
resp = client.chat.completions.create(
    model="qwen3:8b",
    messages=[
        {"role": "system", "content": "你是一个简洁的中文助手"},   # 设定人设，权重最高
        {"role": "user",   "content": "用一句话解释什么是 agent loop"},        # 用户说
    ],
)
print(resp.choices[0].message.content)
print(resp.usage)      # token 计数：prompt_tokens / completion_tokens
```

三种角色必须分清：

| role | 谁在说 | 作用 |
|---|---|---|
| `system` | 你（开发者） | 设定身份、规则、边界，权重最高 |
| `user` | 用户 | 用户输入 |
| `assistant` | 模型 | 模型历史发言（喂回去它才"记得"自己说过什么） |

### 1.2 聊天机器人（01_chat.py，带上下文）

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "qwen3:8b"
SYSTEM = "你是一个简洁的中文助手，回答不超过三句话。"

history = [{"role": "system", "content": SYSTEM}]
print("开始聊天（直接回车退出）")

while True:
    user = input("\n你：").strip()
    if not user:
        break
    history.append({"role": "user", "content": user})
    resp = client.chat.completions.create(model=MODEL, messages=history)
    answer = resp.choices[0].message.content
    print(f"助手：{answer}")
    print(f"（token：输入 {resp.usage.prompt_tokens}，输出 {resp.usage.completion_tokens}）")
    history.append({"role": "assistant", "content": answer})   # 关键行：喂回去才会"记"
```

**三个必看的观察点：**

1. 把 `history.append(assistant)` 那行注释掉再跑——它会彻底失忆。这直观证明了"模型无状态"。
2. 盯着每次的 `prompt_tokens`：它是**累加的**。上下文窗口（qwen3 是 4 万级）/上下文积累/每轮重发全文，这就是 3.x 讲 RAG 和记忆裁剪的动机。
3. 跟它说"记住你喜欢苹果"再聊十句后问它——在窗口内它记得，说明所谓"记忆"只是历史数组够长。

## 第 2 步：手工实现 Function Calling（分水岭）

### 2.1 问题：模型只会说话，怎么"做事"？

答案是**约定**：你提前告诉模型"有一批函数可供调用"，模型不执行任何东西，它只在需要时**吐出一个结构化的 JSON 说"帮我调 get_weather，参数是北京"**，真正执行的是你的 Python 程序，执行完把结果喂回去，模型再基于结果作答。整个流程一轮要走**两次**模型：

```text
用户问："北京该穿什么？"
  → 发 messages + tools 定义给模型
  ← 模型返回 tool_calls（不直接回答）          ← 第 1 次调用
  → 你的代码执行 get_weather("北京") 得到 JSON
  → 把 JSON 以 role="tool" 追加进 messages，再发
  ← 模型基于结果回答"12 度多云，建议穿外套"    ← 第 2 次调用
```

### 2.2 tools 定义逐字段读（02_tool_calling.py 核心段）

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        # description 是给模型看的说明书——写得多清楚，模型调得就多准
        "description": "查询某个城市当前天气",
        "parameters": {                      # 标准 JSON Schema
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名，如'北京'"},
                "date": {"type": "string", "description": "可选，默认今天"},
            },
            "required": ["city"],
        },
    },
}]
```

> **Agent 工程第一课**：工具名、参数名、description 不是写给人看的，是写给模型看的。以后你的 Agent 不可靠，80% 先回头抠这三个地方。

### 2.3 完整一轮手工流程

```python
import json
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

def get_weather(city, date=None):
    # 本地假数据代替真实 API，结构真实即可
    return {"city": city, "date": date or "今天", "天气": "多云转晴", "气温": 12}

final = client.chat.completions.create(
    model="qwen3:8b",
    messages=[{"role": "user", "content": "北京今天该穿什么？先查天气"}],
    tools=tools,
).choices[0].message

print(final.tool_calls)          # ① 看到了什么：模型要求调用
if final.tool_calls:             # ② 你的代码执行
    tc = final.tool_calls[0]
    args = json.loads(tc.function.arguments)
    result = get_weather(**args)
    # ③ 把两条"过程消息"追加回去，再问一次
    messages = [
        {"role": "user", "content": "北京今天该穿什么？先查天气"},
        {"role": "assistant", "tool_calls": [
            {"id": tc.id, "type": "function", "function": {"name": tc.function.name,
             "arguments": tc.function.arguments}}
        ]},
        {"role": "tool", "tool_call_id": tc.id,
         "content": json.dumps(result, ensure_ascii=False)},
    ]
    answer = client.chat.completions.create(
        model="qwen3:8b", messages=messages, tools=tools).choices[0].message
    print(answer.content)
```

**三个必看：**

- 第 1 次返回里 `content` 往往是空的，任务全在 `tool_calls`——这是正常形态。
- `tool_call_id` 必须原样回传，服务端靠它对账"那次调用对应哪个结果"。
- 把 `desc` 里的 description 改成 `"function 1"` 这种垃圾描述，观察模型开始乱调——直观感受工具说明书的价值。

## 第 3 步：把调用改成 while 循环 —— 真 Agent

### 3.1 其实只剩一个 while

第 2 步的"走两次"可以无限套下去：工具结果可能又触发新的工具调用。所以把"两步"抽象成循环，你就写出了 Agent 的最终形态：

```text
while True:
    调模型（带全部 tools + 全部历史）
    if 模型要调工具: 执行 → 结果入历史 → continue
    else: 模型给出了自然语言结论 → 任务完成 → break
```

**任何**框架——LangChain、AutoGen、你现在在用的 OpenCode——剥开外层后都是这个循环。它们只是帮你加了记忆管理、流式输出、错误重试这些工程件。

### 3.2 完整 Agent（03_agent_loop.py 全文逻辑）

三个工具：`get_weather`（假数据）、`get_now`、`calc`（受限计算器）。核心循环：

```python
import json, datetime
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "qwen3:8b"

def get_weather(city):
    return {"city": city, "天气": "多云转晴", "气温": 12}

def get_now():
    return datetime.datetime.now().strftime("%Y-%m-%d %H:%M %A")

def calc(expr):
    if not set(expr) <= set("0123456789+-*/(). "):
        return "仅支持四则运算"
    return eval(expr)   # 已做字符白名单；生产代码请用 ast 求值

DISPATCH = {"get_weather": get_weather, "get_now": get_now, "calc": calc}
SYSTEM = "你是一个能调用工具解决问题的助手。涉及事实信息时必须先调工具，不要猜。"

def run_agent(user_input: str, max_turns: int = 8) -> str:
    history = [{"role": "system", "content": SYSTEM},
               {"role": "user", "content": user_input}]
    for turn in range(1, max_turns + 1):
        print(f"---- 第 {turn} 轮 ----")
        msg = client.chat.completions.create(
            model=MODEL, messages=history, tools=TOOLS,
        ).choices[0].message

        if not msg.tool_calls:                      # 不再要工具 → 任务完成
            return msg.content

        history.append({"role": "assistant", "tool_calls": [
            {"id": t.id, "type": "function", "function": {"name": t.function.name,
             "arguments": t.function.arguments}} for t in msg.tool_calls]})

        for t in msg.tool_calls:                    # 执行每个工具调用
            name, args = t.function.name, json.loads(t.function.arguments)
            print(f"调用 {name}({args})")
            try:
                result = DISPATCH[name](**args)     # 分发到真实 Python 函数
            except Exception as e:
                result = {"error": str(e)}          # 出错也要告诉模型，它会调整
            history.append({"role": "tool", "tool_call_id": t.id,
                            "content": json.dumps(result, ensure_ascii=False)})
    return "达到最大轮数，任务未完成。"

if __name__ == "__main__":
    while True:
        q = input("\n任务> ").strip()
        if not q:
            break
        print(run_agent(q))
```

### 3.3 关键工程细节（每个都是血泪）

1. **max_turns 必须设**：模型可能死循环（反复查同一个天气）。设个上限强制收束。
2. **工具报错要回传给模型**：`{"error": ...}` 而不是自己 raise 崩掉。模型看到错误经常能自己修正（换参数、换工具）——这是 agent 拥有"韧性"的核心机制。
3. **打印每轮动作**：agent 是黑盒调试灾难重灾区，没有 trace 等于盲飞。
4. **工具结果要短**：一次返回 500 行 JSON 会瞬间吃掉上下文。返回前裁剪，只留模型需要的字段。

## 第 4 步：Memory 持久化 + RAG 文档问答

### 4.1 Memory：把对话存进 SQLite（04a_memory.py）

第 1 步的聊天史在进程退出就没了。给它加一个文件大脑——**SQLite 单文件、零配置、标准库自带**，学习期最合适：

```python
import sqlite3, datetime
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "qwen3:8b"
DB = "chat_memory.db"
SYSTEM = "你是一个简洁的中文助手。请参考对话历史中的既有偏好和事实作答。"

def init_db():
    con = sqlite3.connect(DB)
    con.execute("""CREATE TABLE IF NOT EXISTS messages(
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        role TEXT NOT NULL, content TEXT NOT NULL,
        created TEXT NOT NULL)""")

def load_history(limit=50):
    """每次启动读最近 N 条——把'跨会话上限'变成明确的工程参数"""
    con = sqlite3.connect(DB)
    rows = con.execute(
        "SELECT role, content FROM messages "
        "ORDER BY id DESC LIMIT ?", (limit,)).fetchall()
    return [{"role": r, "content": c} for r, c in reversed(rows)]

def save(role, content):
    con = sqlite3.connect(DB)
    con.execute("INSERT INTO messages(role, content, created) VALUES(?, ?, ?)",
                (role, content, datetime.datetime.now().isoformat()))
    con.commit()

def main():
    init_db()
    history = [{"role": "system", "content": SYSTEM}] + load_history()
    print("记忆机器人：『/记忆』查看已存条数，回车退出。跨运行记得你的话。")
    while True:
        user = input("\n你：").strip()
        if not user:
            break
        save("user", user)                          # 先存
        history.append({"role": "user", "content": user})
        answer = client.chat.completions.create(
            model=MODEL, messages=history).choices[0].message.content
        history.append({"role": "assistant", "content": answer})
        save("assistant", answer)                   # 后存
        print(f"助手：{answer}")
        if user == "/记忆":
            con = sqlite3.connect(DB)
            print(con.execute("SELECT COUNT(*) FROM messages").fetchone())
```

跑一次，告诉它你叫什么，**退出重进**再问它——它记得。这就是"长期记忆"的全部秘密：**只是把 messages 数组存下来了**。商业产品的"记忆"概念，往复杂了做是用户画像摘要、自动压缩，根子上就是这个。

值得停下来想两个真实产品级问题（不要求现在实现，但要知道）：

- **加载多少**？全部历史烧 token，最近 50 条可能丢掉早期偏好 → 生产会用"摘要+最近 N 条"分层。
- **灵敏度**？`load_history(limit=…)` 这个数字，就是你的第一个"记忆策略"参数。

### 4.2 RAG：让模型回答"它不知道的事"（04b_rag.py）

模型只见过训练数据，回答不了你自己公司文档的问题。RAG（检索增强生成）五步：**切块 → 向量化 → 检索 → 拼进 prompt → 让模型基于这段内容回答**。用 bge-m3 做向量（中文友好），numpy 算相似度，不引库：

```python
import os, glob
import numpy as np
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
# 与 code\04b_rag.py 实际实现一致：按脚本所在位置向上找 docs 目录，可随目录整体搬迁
DOCS_DIR = os.path.join(os.path.dirname(__file__), "..", "docs")

# 第 1 步：读语料
documents = {}
for path in glob.glob(os.path.join(DOCS_DIR, "*.txt")) + glob.glob(
        os.path.join(DOCS_DIR, "*.md")):
    with open(path, "r", encoding="utf-8") as f:
        documents[path] = f.read().replace("\n\n", "\n")

# 第 2 步：切块（页尾 50 字重叠避免答案恰好跨块被腰斩）
CHUNK = 400
chunks, owners = [], []
for doc_name, text in documents.items():
    for i in range(0, len(text), CHUNK - 50):
        chunks.append(text[i:i + CHUNK])
        owners.append(doc_name)
print(f"已加载 {len(documents)} 个文件，切出 {len(chunks)} 块")

# 第 3 步：向量化（bge-m3 负责把文字变成语义坐标）
vecs = np.asarray([client.embeddings.create(
    model="bge-m3", input=[c]).data[0].embedding for c in chunks])

def search(query: str, k: int = 4):
    qe = np.asarray(client.embeddings.create(
        model="bge-m3", input=[query]).data[0].embedding)
    sims = (vecs @ qe) / (np.linalg.norm(vecs, axis=1) + 1e-9) / np.linalg.norm(qe)
    top = sims.argsort()[::-1][:k]
    return [i for i in top]

SYSTEM = "只依据给定资料回答。资料没有就说'资料未提及'，不要编。"

user = input("\n问题> ")
hit = []
for i in search(user):
    hit.append(f"【资料片段】【{os.path.basename(owners[i])}】\n{chunks[i]}")
context = "\n---\n".join(hit)

answer = client.chat.completions.create(
    model="qwen3:8b",
    messages=[{"role": "system", "content": SYSTEM + "\n\n资料：\n" + context},
              {"role": "user", "content": user}]).choices[0].message.content
print(answer)
```

**必看的三个点：**

1. **RAG 没有"魔法"**——只是把"找相似文本"做成向量夹角余弦，塞进 prompt。考验你的信息检索基本功。
2. **切块参数极重要**：每块 400 字、50 字重叠就是你的第一版检索策略。检索不到正确的块，后面的回答必然错。
3. **在 docs/示例笔记.txt 里写一段只有此处才有的话**（比如自造一个名词及其解释），然后向 RAG 程序提问这个词——只有检索命中才能答对，验证检索链路确实生效（纯模型应该不知道）。

## 常见问题排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| `Connection refused / connect 11434` | Ollama 没跑 | `ollama serve` 或托盘图标启动 |
| `model "qwen3:8b" not found` | 没拉模型 | `ollama pull qwen3:8b` |
| 回答前先长时间输出 `<think>…` | qwen3 的思考模式开着 | 用户消息末尾加 `/no_think` 可关；agent loop 建议关掉（省钱省时） |
| 模型从不调工具，直接瞎编 | 工具描述太烂 / 模型没开工具支持 | 抠 description；确认模型是 instruct 版 |
| `tool_calls` 里 arguments 是坏 JSON | 小模型偶尔吐坏参 | try/except 后把错误回传给模型，它会重试 |
| python 中文乱码 | GBK 控制台 | 不建议 `chcp 65001`，直接用 Windows Terminal 运行 |
| RAG 答非所问"编造" | 检索没命中正确块 | 打印 top-k 片段看哪错了，先查切块再查负归因 |
| 每个 agent 轮次等 5~10 秒 | 4070S 上 8B 的现实速度 | 用 `/no_think`；调试期把 max_turns 减小、打印 turn 进度 |
