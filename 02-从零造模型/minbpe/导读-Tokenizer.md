## 一、BPE 是在干什么（一段话版）

模型只能吃数字，所以文本要先编码成整数序列。**BPE（字节对编码）的做法**：先把文本按 UTF-8 拆成 0~255 的字节序列，然后反复执行"数一遍哪对字节挨得最多 → 给这对起一个新编号 → 之后它出现就用新编号"——执行 N 次后，高频片段（如"宫""en""，"）就有了自己的专属 token，低频内容继续用字节表示。

就这么简单。GPT/Qwen 几十万 token 的词表，核心算法和你 32 步训练的 demo 是同一个。

## 文件地图与读法

```text
minbpe\minbpe\
├── basic.py    ★ 先读：90 行，全部算法在内
│   ├── train()   → 训练：bytes → 反复合并 → 词表
│   ├── encode()  → 编码：按"合并时间最早优先"回放合并规则
│   └── decode()  → 解码：查表拼回字节，再转字符串
├── base.py     然后：get_stats() 统计相邻对 / merge() 执行替换（共 20 行真算法）
│                以及 save/load（词表存盘格式，可跳读）
└── regex.py / gpt4.py   后置：加上 GPT 的正则切分和特殊 token（生产坑，非原理坑）
```

## 你的 demo 已经证明了三件事

跑 `python 00_train_demo.py`，对着输出逐条理解：

1. **merge 日志里全是高频内容**：`b' '` 空格对（2409 次）、`的`（264 号）、`，`（266 号）——词表自动长成"语料的高频摘要"；
2. **英文占便宜**：`en/on/es/ol` 都成为新 token，而中文每字 2~3 字节只能慢慢合并——demo 末尾中文 2.68 token/字 vs 英文 0.95 token/字符，就是"中文费 token"的现场证据；
3. **可逆性**：`decode(encode(x)) == x` 这条断言，是所有 tokenizer 的工程底线（Qwen 词表也一样要过这关）。
